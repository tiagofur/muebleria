# #805 — G-ODD v1.1 state and catalog simplification

## Objective

Deliver one isolated factory/process pull request that reduces routine startup
context and duplicated state by removing the global `progress/current.md`, making
the issue-scoped ODD artifact the only durable execution record for substantial
ODD work, and replacing the implementation ledger in `feature_list.json` with a
small catalog of genuine high-level product capabilities.

## Problem

The current factory correctly treats GitHub, code, tests, and exact candidate
evidence as authoritative, but two legacy surfaces still impose avoidable cost:

- `progress/current.md` duplicates live issue/PR state and requires conflict-prone
  cleanup after work finishes.
- `feature_list.json` contains 215 implementation rows across 477,954 bytes and
  5,888 lines, including fixes, refactors, reviews, tests, slices, execution state,
  and historical evidence that belong in Git and GitHub.

Routine `factory_preflight.py` still parses the catalog on every start. Live
factory instructions also retain references to the removed global ledger, and
some factory tests pin issue-specific historical narrative instead of reusable
semantic contracts.

## Why

G-ODD v1.1 should preserve feature continuity without session continuity: one
issue maps to at most one durable execution artifact, while GitHub Issues/PRs own
queue, approval, and global state; code/tests own implemented truth; and Engram is
only an optional mirror. Removing redundant state reduces startup tokens,
conflicts, stale status, and administrative commits without weakening G-ODD v1.0
controls.

## Scope

- Delete `progress/current.md` and remove it from live factory/process
  instructions, scripts, tests, documentation, and startup behavior.
- Define `odd/tasks/<issue>-<slug>.md` as the sole durable execution artifact for
  substantial ODD work. Direct remains artifact-free; explicit SDD uses only its
  canonical artifact.
- Keep completed ODD issue artifacts in `odd/tasks/` as immutable history that is
  never scanned globally or loaded at startup.
- Simplify `feature_list.json` into a compact, stable catalog of genuine product
  capabilities with no queue, scheduler, ownership, reservation, priority, or
  execution state.
- Align factory entrypoints, role skills, verification guidance, CI validation,
  and semantic drift tests with the reduced state model.
- Report exact before/after bytes, lines, catalog entries, and routine startup
  read paths.

## Non-goals

- Product behavior, product source logic, migrations, generated contracts, or
  product tests.
- Rebuilding the factory, adding a scheduler/dispatcher/daemon, enabling
  receipt-driven review, or changing existing product verification requirements.
- Creating `odd/archive/`, moving artifacts after merge, or requiring a later
  cleanup commit.
- Adding `scripts/factory_status.py`. It cannot distinguish active work from
  retained historical artifacts offline without duplicating GitHub/ownership
  state or introducing stale status metadata.
- Adding front matter to ODD artifacts. The filename already identifies the issue
  and the directory already identifies the ODD lane.
- Merging the PR, closing #805 manually, force-pushing, bypassing gates, or
  granting protected labels without current maintainer authority.
- A full review or rewrite of the broader `docs/` tree beyond live contradictions
  directly caused by this process change.

## Acceptance criteria

- `progress/current.md` no longer exists, and no live factory/process authority
  reads, writes, recommends, or depends on a global current ledger.
- Routine startup reads the approved issue, role/contract, ownership, and affected
  sources only; `factory_preflight.py` does not parse `feature_list.json` or any
  global progress ledger.
- Substantial ODD uses exactly one `<issue>-<slug>.md`; Direct creates none;
  explicit SDD creates no duplicate ODD artifact; no session/review-round files
  are introduced.
- Completion requires no post-merge cleanup: the final issue artifact stays in
  `odd/tasks/` as immutable, non-startup history.
- `feature_list.json` contains only consolidated high-level product capabilities
  and minimal stable catalog metadata. It contains no bugs, CSS corrections,
  reviews, fixes, tests, implementation slices, microchanges, queue/scheduler/
  ownership data, or execution state.
- A deterministic schema/validator rejects operational fields or categories and
  duplicate/invalid capability identifiers.
- Removed operational history remains recoverable from Git, Issues, and PRs; no
  critical product capability is lost during consolidation.
- No `factory_status.py`, `odd/archive/`, artifact front matter, product behavior,
  merge, or manual issue closure is introduced.
- G-ODD v1.0 controls remain explicit and protected by focused semantic tests.
- Final reporting records exact before/after catalog bytes, lines, and entries;
  confirms removal of the original 7,226-byte/107-line global current file and its
  rebased 7,429-byte/107-line version; and names every path removed from routine
  startup reads.
- Focused factory tests, syntax/schema checks, proportional planning, exact-head
  CI, and fresh independent review are reported honestly for the frozen candidate.
