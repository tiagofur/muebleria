## Límites
- Históricos y handoffs conservan su temporalidad; APPROVED/PASS no se promueven al SHA actual.
- CORRECT certifica sólo el claim contrastado o la naturaleza explícita de método/redirect, nunca todas las frases.
- Cada fila JSON nombra la afirmación y la próxima prueba específica pendiente.
- No se ejecutó producto, host, pruebas, DB ni scripts de recuperación.

## Key Learnings:
1. El manual de uso todavía enseña registro/aprobación que fue reemplazado por invitation-first.
2. El README SketchUp describe credenciales obsoletas pese que el runtime ya usa DeviceProvider/secure store.
3. Un review histórico puede justificar una decisión entonces válida sin demostrar seguridad física del producto actual.
